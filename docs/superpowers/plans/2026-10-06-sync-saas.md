# Accord SaaS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Execution method must be selected by the user before implementation.

**Goal:** Transformer le service personnel en application web payante permettant de configurer des synchronisations Todoist, Notion et Google Calendar sans terminal.

**Architecture:** Une application React et une API Hono tournent sur Cloudflare Workers. D1 stocke comptes, configuration et opérations ; un Durable Object par utilisateur orchestre les écritures et Queues déclenche les reprises. Le service Node actuel reste utilisable pendant la migration, sans partager sa base avec le SaaS.

**Tech Stack:** TypeScript strict, pnpm, React/Vite, Tailwind, shadcn/ui, Hono, Drizzle/D1, Better Auth, Workers/Durable Objects/Queues/Cron, Stripe, Vitest et tests navigateur.

**Spec:** [Design validé](../specs/2026-10-06-sync-saas-design.md).

## Global Constraints

- Cible initiale individuelle, interface française, architecture préparée pour la traduction.
- Un compte connecté par fournisseur au lancement.
- Nom de travail : « Accord » (nom et domaine non vérifiés).
- Une formule unique proposée à 6 €/mois avec 14 jours d'essai sans carte ; prix configurable côté serveur, pas encore une décision commerciale.
- Le code existant demeure disponible pendant la migration. La base personnelle ne doit être ni modifiée ni importée automatiquement.
- Pas d'avis clients, logos de clients ou statistiques inventés.
- Tout fonctionne au clavier et sur mobile. Erreurs et chargements explicites.
- Mode démonstration local clairement identifié, isolé des données réelles.
- Aucune suppression définitive de tâche Todoist.
- Ne pas promettre une traduction universelle des récurrences ou du temps réel.
- Pas d'auto-planification ou d'IA dans cette version.
- Les mocks ne constituent pas une validation réelle des fournisseurs.
- Aucun secret lu dans `.env` existant, ni base `data/` consultée pour construire le SaaS.
- Aucune ressource distante, dépense ou mise en production créée par l'exécution locale.

## Review Focus

1. Durée d'une tâche traversant le passage à l'heure d'hiver : durée réelle préservée, date locale non décalée (tâche 8).
2. Accès Notion révoqué ou propriété renommée : connexion/règle bloquée avec explication, aucune suppression propagée (tâche 10).
3. Crash après création externe avant sauvegarde du lien : retrouver le miroir avant de retenter une création (tâche 9).
4. Deux fenêtres modifiant une règle : refuser la version périmée, sans écraser une configuration récente (tâche 5).
5. Fin d'essai ou déconnexion pendant un travail déjà en file : revérifier les droits immédiatement avant les écritures (tâche 11).

export type Field = 'title' | 'description' | 'schedule' | 'completed' | 'priority'
export type Schedule =

  deleted: boolean

export interface Rule {
  id: string
  userId: string

  name: string
  source: ResourceRef
  destination: ResourceRef
  direction: 'one-way' | 'two-way'
  fields: Field[]
  filters: { sectionIds: string[]; labels: string[]; priorities: number[]; datedOnly: boolean }
  options: {

    eventDeletion: 'unlink' | 'complete'
    completion: 'mark' | 'remove'
    maxMutations: number
  }

    title: string; date: string; status: string
    doneValues: string[]; openValue: string; doneValue: string
    priority?: string
  } | null

}

}

}
export interface Operation {
  id: string; userId: string; ruleId: string; ruleRevision: number

## Critères de fin et limites externes

Le code local est livré lorsque les 12 tâches et leurs vérifications passent,
que tous les écrans sont fonctionnels et que les secrets absents ont un état
explicite. La démo seule, un paiement simulé ou un adapter mock ne suffisent pas.

La mise en service exige des comptes OAuth dédiés, domaine, Cloudflare,
clés Stripe de test puis de production, vérification Google si applicable et
textes légaux finalisés. Ces éléments seront demandés au moment où ils deviennent
nécessaires pour tester/publier ; pas pour commencer le code local.
